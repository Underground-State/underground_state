# Underground State — Экономическая модель

## Обзор

Экономика платформы построена на принципе **gas-on-everything**: каждое действие имеет стоимость или приносит доход. Это создаёт устойчивую экономику, защиту от спама и стимулы для всех участников.

## Токены

### UGS (Underground State Token)

Основной utility-токен платформы:
- Оплата всех действий на платформе
- Голосование в DAO
- Стейкинг для репутационных действий
- Оплата провайдерам инфраструктуры

### INV (Investor Token)

Геймификационный токен раннего вклада:
- Выдаётся за бесплатный хостинг в ранней фазе
- Выдаётся за активность до запуска основной экономики
- Proof of early contribution
- Торгуется на DEX (после запуска пулов)
- Пулы ликвидности UGS/INV (в будущем)

## Фазы экономики

### Фаза 1: Рост (Ранняя)

| Участник | Действие | Результат |
|----------|----------|-----------|
| Пользователь | Общается | **Зарабатывает** UGS |
| Провайдер | Хостит бесплатно | **Получает** INV tokens |
| Создатель контента | Публикует | **Зарабатывает** UGS |

Цель: привлечение пользователей и провайдеров, создание сетевого эффекта.

### Фаза 2: Зрелая

| Участник | Действие | Результат |
|----------|----------|-----------|
| Пользователь | Общается | **Платит** UGS |
| Провайдер | Хостит | **Получает** UGS |
| Создатель контента | Публикует | **Зарабатывает** (читатели платят) |

**Переход между фазами контролируется голосованием DAO.**

## Инфраструктурные провайдеры

### Типы провайдеров

| Тип | Сервис | Метрики оплаты |
|-----|--------|----------------|
| RPC Node | Обработка запросов | requests/sec, uptime |
| WebSocket Provider | Realtime каналы | connections, bandwidth |
| Video CDN | Видеотрансляции | quality, duration, bandwidth |
| Voice Provider | Голосовые звонки | minutes, quality |

### Формула выплат

```
Payment = base_rate × quality_multiplier × uptime_hours

quality_multiplier = f(bitrate, latency, packet_loss)

где:
  bitrate > threshold     → multiplier += 0.2
  latency < 50ms          → multiplier += 0.3
  packet_loss < 0.1%      → multiplier += 0.2
  uptime > 99.9%          → multiplier += 0.3
```

### Метрики качества

**Для видео:**
- `bitrate` — качество картинки (kbps)
- `resolution` — разрешение (720p, 1080p, 4K)
- `frame_rate` — частота кадров (fps)
- `buffering_ratio` — процент буферизации

**Для голоса:**
- `audio_bitrate` — качество звука
- `jitter` — джиттер (ms)
- `latency` — задержка (ms)

**Общие:**
- `uptime` — время доступности (%)
- `requests_served` — обработанные запросы
- `bandwidth_provided` — предоставленная пропускная способность

## Защита от злоупотреблений

### Anti-spam

| Проблема | Решение |
|----------|---------|
| Спам сообщений | Каждое сообщение стоит gas |
| Боты/скрейпинг | Чтение стоит gas |
| Массовые репорты | Stake сгорает при ложном обвинении |
| DDoS на профили | Каждый запрос стоит gas |
| Мусорные гильдии | Создание гильдии дорогое |

### Репутационный стейкинг

```
┌─────────────────────────────────────────────────────────────┐
│              МЕХАНИКА РЕПУТАЦИОННОГО СТЕЙКА                 │
├─────────────────────────────────────────────────────────────┤
│                                                             │
│  1. User A видит токсичное поведение User B                │
│  2. A стейкает 1 UGS → создаёт report                      │
│  3. Другие пользователи могут подтвердить (+stake)         │
│                                                             │
│  Если report подтверждён (N голосов):                      │
│    • B получает +1 к toxicity score                        │
│    • Стейки возвращаются голосовавшим + бонус              │
│                                                             │
│  Если report отклонён:                                      │
│    • Стейк A сгорает                                       │
│    • Часть идёт B как компенсация                          │
│                                                             │
└─────────────────────────────────────────────────────────────┘
```

2. **Governance вес** — INV holders получают бонус к голосам
3. **Конвертация** — возможность обменять INV → UGS с бонусом
4. **Эксклюзивный доступ** — ранние фичи для INV holders

## DAO Governance экономики

### Что контролирует DAO

- Переход между фазами экономики
- Размер gas для каждого действия
- Пропорции распределения (автор/провайдер/treasury/burn)
- Пороги качества для провайдеров
- Курс конвертации INV → UGS
- Параметры репутационного стейкинга

### Процесс изменения

```
1. Создание proposal (стоит 5 UGS)
2. Обсуждение (7 дней)
3. Голосование (3 дня)
4. Исполнение (автоматически через smart contract)
```

## Криптографический контроль доступа

### Принцип

Каждый пользователь контролирует доступ к своей информации криптографически:

```
┌─────────────────────────────────────────────────────────────┐
│           КРИПТОГРАФИЧЕСКИЙ ПЕРСОНАЛЬНЫЙ БАН                │
├─────────────────────────────────────────────────────────────┤
│                                                             │
│  User A банит User B:                                       │
│  • B не может прочитать сообщения A (нет ключа)            │
│  • B не видит профиль A                                    │
│  • B не может узнать что A существует                      │
│                                                             │
│  Обойти НЕВОЗМОЖНО:                                        │
│  • Новый кошелёк → нет репутации → фильтр по умолчанию    │
│  • Платформа не может разбанить — нет ключей              │
│                                                             │
└─────────────────────────────────────────────────────────────┘
```

### Автоматический фильтр по репутации

```
Настройки пользователя:
  toxicity_threshold: 30
  aggression_threshold: 50
  auto_ban_on: [fraud, spam]

→ Все кто превышает пороги автоматически теряют доступ
```

### Подпись на чтение

```
GET /message/123
Authorization: session_key_signature

• Каждый запрос на чтение подписывается session key
• Сервер хранит только зашифрованные данные
• Без подписи → данные недоступны даже серверу
• Court order → "у нас нет ключей, только шифр"
```
